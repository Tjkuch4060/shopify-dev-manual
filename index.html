Architecture Overview

Understand how a Shopify store works under the hood.

The Big Picture

Shopify is a hosted commerce platform. You write themes (frontend) and apps (backend) that plug into Shopify's infrastructure.

Customer Browser
Renders HTML/CSS/JS
Liquid Theme
Templates + Sections + Snippets
Shopify Server
Renders Liquid to HTML
Shopify Admin
Store settings and data
Apps and APIs
REST / GraphQL / Webhooks
Database
Products, Orders, Customers

Key Concepts

1. Liquid

Server-side templating language. Runs on Shopify's servers, outputs pure HTML.

2. Online Store 2.0

Current theme architecture with JSON templates — merchants build pages by dragging sections.

3. Themes vs. Apps

AspectThemesApps
PurposeStorefront appearanceBusiness logic
LanguageLiquid, HTML, CSS, JSAny (Node, Ruby, PHP…)
HostingShopify CDNYour servers
Data accessRead-only via LiquidRead/write via APIs

Key insight: You never write server-side PHP/JS for a themed Shopify store. Liquid IS your server-side language.

Dev Environment Setup

Get your local environment running with the Shopify CLI.

Prerequisites

  • Node.js 18+ installed
  • Git installed
  • Shopify Partner account created
  • Development store created in Partner Dashboard
  • Code editor ready (VS Code recommended)

Install the CLI

Terminal
npm install -g @shopify/cli @shopify/theme

Start a Theme

Terminal
shopify theme init my-theme
cd my-theme
shopify theme dev --store your-store.myshopify.com
Terminal
shopify theme pull --store your-store.myshopify.com
shopify theme list --store your-store.myshopify.com

Run shopify theme check at any time to catch Liquid errors, missing schema fields, and accessibility issues before pushing.

Theme

Theme Structure

Every Shopify theme follows a strict file hierarchy.

your-theme/ config/ settings_schema.json layout/theme.liquid templates/ index.json product.json collection.json cart.json page.json blog.json article.json 404.json sections/ header.liquid footer.liquid main-product.liquid … snippets/ product-card.liquid icon.liquid … assets/ base.css application.js locales/en.default.json

Shopify loads layout/theme.liquid for every page. The {{ content_for_layout }} tag inside it is replaced by the JSON template for that page type, which pulls in its sections, which pull in snippets.

Always use render over include. It's faster and has isolated scope — variables from the parent don't leak into the snippet.

Theme

JSON Templates

Define which sections appear on a page, their order, and their default settings.

JSON — templates/product.json
{
  "sections": {
    "main": {
      "type": "main-product",
      "settings": {}
    },
    "recommendations": {
      "type": "product-recommendations",
      "settings": { "heading": "You may also like" }
    }
  },
  "order": ["main", "recommendations"],
  "layout": "theme"
}
  • Section IDs are arbitrary keys — "order" references them by those keys.
  • block_order inside a section controls block sequence.
  • "disabled": true hides a section without deleting it.
  • Alternate templates use dot notation: product.gift-card.json.

A section listed in "order" must also exist in "sections" — mismatches silently produce blank pages.

API

Storefront API

Public GraphQL API for headless commerce and dynamic AJAX operations.

Themed stores rarely need this directly. Liquid already exposes all product, collection, and cart data server-side. Use the Storefront API only when you need dynamic client-side data (e.g., cart AJAX, product availability polling).

JavaScript
async function storefrontQuery(query, variables = {}) {
  const res = await fetch('/api/2024-01/graphql.json', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-Shopify-Storefront-Access-Token': TOKEN
    },
    body: JSON.stringify({ query, variables })
  });
  return res.json();
}

// Example: fetch product by handle
const { data } = await storefrontQuery(`
  query ProductByHandle($handle: String!) {
    product(handle: $handle) {
      title
      priceRange { minVariantPrice { amount currencyCode } }
    }
  }
`, { handle: 'classic-sneaker' });

Generate a Storefront access token in Admin → Apps → Develop apps → your app → API credentials.

Extend Shopify by building apps that react to store events in real time.

Always verify webhook signatures using HMAC-SHA256. Never trust a payload without verification.

Published on the Shopify App Store. OAuth required for installation. Best for reusable tools sold to many merchants.

Created directly in Admin. No App Store review. Single-store only. Best for ERP sync, custom fulfillment, and internal tooling.

Inject blocks into sections via app embeddings — no theme file edits required. Best for reviews widgets, size charts, and loyalty badges.

Best Practices

Fast, accessible, maintainable, merchant-friendly themes.

Images — Always Use picture + WebP

Liquid
<picture>
  <source srcset="{{ image | image_url: width: 800, format: 'webp' }}" type="image/webp">
  <img
    src="{{ image | image_url: width: 800 }}"
    width="{{ image.width }}"
    height="{{ image.height }}"
    loading="lazy"
    decoding="async"
    alt="{{ image.alt | escape }}"
  >
</picture>

Accessibility Checklist

  • All images have meaningful alt text
  • Semantic HTML (<nav>, <main>, <article>)
  • WCAG AA contrast ratios on all text
  • Keyboard-focusable interactive elements
  • aria-label on icon-only buttons
  • Run shopify theme check before every push

snippets/countdown-timer.liquid+ JSMedium

Displays a live HH:MM:SS countdown to a deadline set in section settings. When time expires the element hides itself automatically.

Liquid
{% comment %} Usage: {% render 'countdown-timer', deadline: section.settings.sale_end %} {% endcomment %}
{% if deadline != blank %}
<div id="countdown-wrap" style="
  display:inline-flex; gap:6px; align-items:center;
  font-family:monospace; font-size:15px; font-weight:700;">
  <i class="fas fa-clock" style="color:#e05555;"></i>
  <span id="countdown-display"></span>
</div>
<script>
(function() {
  var end  = new Date("{{ deadline }}").getTime();
  var wrap = document.getElementById('countdown-wrap');
  var disp = document.getElementById('countdown-display');
  if (!wrap || isNaN(end)) return;

  function pad(n) { return String(n).padStart(2,'0'); }
  function tick() {
    var diff = end - Date.now();
    if (diff <= 0) { wrap.style.display = 'none'; return; }
    var h = Math.floor(diff / 3600000);
    var m = Math.floor((diff % 3600000) / 60000);
    var s = Math.floor((diff % 60000)   / 1000);
    disp.textContent = pad(h) + ':' + pad(m) + ':' + pad(s);
  }
  tick();
  setInterval(tick, 1000);
})();
</script>
{% endif %}

  • Collections created and products organized

Email Notifications

  • Google Analytics / GA4 connected

The Theme Editor

The theme editor is where you change how your site looks without touching code. Think of it like Canva for your website — you can change colors, fonts, images, text, and rearrange sections by clicking and typing.

How to open it: Admin → Online Store → Customize

Changing Colors and Fonts

  1. Open the theme editor (Admin → Online Store → Customize)
  2. Click the paintbrush icon in the left panel
  3. Under Colors, click any swatch and enter a hex code or pick from the palette
  4. Under Typography, choose heading and body fonts from the dropdowns
  5. Click Save in the top-right corner

Always click Save. Closing the editor without saving discards your changes.

Adding, Moving, and Hiding Sections

  1. In the theme editor, click Add section at the bottom of the left panel
  2. Pick a section type from the list
  3. Drag the handle (⠿) to reorder sections
  4. Click the eye icon next to any section to hide it without deleting

Sections are per-page. Changes on the homepage don't affect product pages, and vice versa.

Products

Adding a New Product

  1. Go to Products → Add product
  2. Enter a descriptive title ("Women's Blue Linen Shirt" not "Shirt #1")
  3. Write a description covering materials, sizing, and care
  4. Set the price
  5. Upload at least 3–5 product photos (800px minimum, 2000px ideal)
  6. Click Save

Fulfilling an Order

  1. Open the order (Admin → Orders)
  2. Click Fulfill items
  3. Enter the tracking number from your shipping carrier
  4. Click Fulfill items — the customer gets a shipping email automatically

Issuing a Refund

  1. Open the order
  2. Click Refund
  3. Select the items and choose to restock or dispose
  4. Enter the refund amount and a reason
  5. Click Refund

Refunds process through your payment provider. Money typically appears back in the customer's account within 3–10 business days.

  • Adding new section or page layouts
  • Changing how the header or footer works
  • Adding custom JavaScript (popups, sliders, animations)
  • Modifying checkout appearance or behavior
  • Creating custom email templates

  • Site looks broken after a theme or app update
  • A section disappeared or looks wrong
  • You accidentally deleted something important
  • Pages loading slowly after adding or removing apps
  • Redesigning the entire store
  • Moving to a headless setup
  • Building a custom app
  • Performance optimization (Lighthouse 80+)

Metafields & Metaobjects

Store custom data on any Shopify resource — no app required. The key to building truly custom storefronts.

When do you need this? Whenever you want to attach structured data to a product, variant, collection, or page that doesn't fit into standard Shopify fields — ingredients, specifications, fit guides, certifications, related videos, etc.

Metafields vs. Metaobjects

MetafieldsMetaobjects
WhatCustom fields attached to an existing resource (product, page, etc.)Standalone custom content types you define (like a "Team Member" or "Size Chart")
ExampleAdding "Care Instructions" to every productA "Testimonial" type reusable across the site
Accessproduct.metafields.namespace.keyshop.metaobjects.type.handle or via Liquid metaobject references
Set up inAdmin → Settings → Custom dataAdmin → Settings → Custom data → Metaobject definitions

Setting Up Metafields

  1. Go to Admin → Settings → Custom data
  2. Choose the resource type (Products, Variants, Collections, Pages, etc.)
  3. Click Add definition
  4. Set a Namespace (e.g. custom) and Key (e.g. care_instructions)
  5. Choose a Type (single line text, rich text, number, file, color, JSON, etc.)
  6. Enable Storefront access if you need it via the Storefront API

Use custom as your namespace for store-specific fields. Reserve other namespaces (e.g. reviews, seo) for apps that may write to the same resource.

Accessing Metafields in Liquid

Liquid
{% comment %} Syntax: resource.metafields.namespace.key {% endcomment %}

{{ product.metafields.custom.care_instructions }}
{{ product.metafields.custom.ingredient_list }}
{{ product.metafields.custom.video_url }}

{% comment %} Output the value of a specific type {% endcomment %}
{% assign specs = product.metafields.custom.specifications.value %}
{% for spec in specs %}
  <li>{{ spec }}</li>
{% endfor %}

{% comment %} Rich text metafields use .value {% endcomment %}
{{ product.metafields.custom.care_instructions.value }}

Always check if a metafield exists before outputting it: {% if product.metafields.custom.care_instructions != blank %} — otherwise you'll render an empty element.

Metaobjects

Metaobjects are custom content types you define once and reuse anywhere. Think of them like a lightweight CMS: you define the schema, merchants fill in the entries, and you render them in Liquid.

  1. Go to Admin → Settings → Custom data → Metaobject definitions
  2. Click Add definition, give it a type handle (e.g. team_member)
  3. Add fields: name (single line text), role (single line text), photo (file reference), bio (multi-line text)
  4. Go to Admin → Content → Metaobjects to add entries
  5. Reference entries in Liquid via a metaobject_reference metafield, or loop all entries with the Storefront API

Rendering a Metaobject Reference in Liquid

Liquid
{% comment %}
  Product has a metafield: custom.fit_guide → metaobject_reference
  The referenced metaobject type: fit_guide (fields: title, image, chart_html)
{% endcomment %}

{% assign fit = product.metafields.custom.fit_guide.value %}
{% if fit != blank %}
  <div class="fit-guide">
    <h3>{{ fit.title }}</h3>
    {% if fit.image != blank %}
      <img src="{{ fit.image | image_url: width: 800 }}" alt="Fit Guide">
    {% endif %}
    {{ fit.chart_html }}
  </div>
{% endif %}

When you need all entries of a metaobject type (e.g. all team members for a page), use the Storefront API — Liquid can only access metaobjects attached to a specific resource via a reference field.

JavaScript
const query = `{
  metaobjects(type: "team_member", first: 20) {
    nodes {
      handle
      field(key: "name")   { value }
      field(key: "role")   { value }
      field(key: "bio")    { value }
    }
  }
}`;
const { data } = await storefrontQuery(query);

Don't use metafields for data that changes frequently (e.g. live inventory, pricing). They're cached aggressively. For dynamic data, use the Storefront API or Cart API from JavaScript.

Shopify Functions

Server-side logic that runs on Shopify's own infrastructure — customize discounts, cart behavior, delivery, and payments without a hosted server.

What makes Functions different: Unlike webhooks (which react after an event), Functions intercept Shopify's own processing pipeline. They run inside Shopify in under 5ms, compiled to WebAssembly. You write JS/TS or Rust — Shopify runs it.

Function Types

Function TypeWhat You Can Do
DiscountsTiered pricing, BOGO, volume discounts, custom coupon logic
Cart and Checkout ValidationBlock checkout if cart rules aren't met (min quantity, restricted combos)
Cart TransformMerge, expand, or modify line items before checkout (bundle unpacking)
Delivery CustomizationHide, rename, or reorder shipping options based on cart contents
Payment CustomizationHide or reorder payment methods (e.g. hide COD for high-value orders)
Order RoutingDirect fulfillment to specific locations based on custom rules

Creating a Function

Functions must live inside a Shopify app — they can't be standalone. If you only need a discount, a Custom App (Admin → Apps → Develop apps) is the lightest-weight approach.

The Input / Output Model

Every Function receives a JSON input (cart contents, customer data, products, metafields) and must return a JSON output (operations to apply). You write a GraphQL query to declare exactly which input fields you need.

JavaScript — input.graphql
query Input {
  cart {
    lines {
      quantity
      merchandise {
        ... on ProductVariant {
          id
          product {
            id
            hasAnyTag(tags: ["volume-deal"])
          }
        }
      }
    }
  }
}
JavaScript — index.js
import { InputQuery, FunctionResult, DiscountApplicationStrategy } from "../generated/api";

const DISCOUNT_STRATEGY = DiscountApplicationStrategy.First;

export function run(input) {
  const targets = [];
  const discounts = [];

  for (const line of input.cart.lines) {
    const variant = line.merchandise;
    if (!variant?.product?.hasAnyTag) continue;

    // 10% off if qty >= 3, 20% off if qty >= 6
    let pct = 0;
    if (line.quantity >= 6) pct = 20;
    else if (line.quantity >= 3) pct = 10;
    if (pct === 0) continue;

    targets.push({ cartLine: { id: variant.id } });
    discounts.push({
      targets,
      value: { percentage: { value: String(pct) } },
      message: `Volume deal: ${pct}% off`
    });
  }

  return {
    discounts,
    discountApplicationStrategy: DISCOUNT_STRATEGY
  };
}
JSON — example output

Practical Use Cases

Automatic percentage off based on quantity in cart. Tag products with volume-deal, read the tag in your input query, apply the discount in your function. No discount code needed — fires automatically at checkout.

Use a Delivery Customization function to hide "Express Shipping" if the cart contains a pre-order item, or hide "Local Pickup" if the customer's province isn't in your delivery zone. Read cart.deliveryGroups in your input, return a hideOperation for each method to suppress.

Cart and Checkout Validation functions can return errors that block the customer from proceeding. Example: require a minimum order of $50, or prevent mixing sale and full-price items in the same cart.

JavaScript — validation output
// Block checkout with a message
return {
  errors: [{
    localizedMessage: "Minimum order is $50. Add more to continue.",
    target: "cart"
  }]
};

A merchant sells a "Starter Kit" product. When it hits the cart, a Cart Transform function expands it into its 3 component line items — each with its own fulfillment, inventory, and pricing. The customer sees the bundle; fulfillment sees individual items.

Test locally with mocked input: Create a src/run.test.js file and pass fixture JSON directly to your run() function. No need to go through the full dev tunnel for unit-testing logic.
